# 软件估算模型与功能点法

软件估算模型旨在项目初期科学地预测开发软件所需的工作量（通常以“人月”为单位）和财务成本。**功能点分析法（FP）和 COCOMO 模型是软件工程与管理学中的核心考点。**

---

## 📐 功能点分析法 (FP, Function Point)

*   **定义**：一种从**用户外部视角**度量软件规模的结构化技术。它**与所使用的实现技术（编程语言、框架）完全无关**，适合在项目早期的需求阶段执行。
*   **计算公式**：
    $$FP = UFP \times TCF$$
    （其中：$UFP$ 为未调整功能点数，$TCF$ 为技术复杂度调整因子，范围在 $0.65 \sim 1.35$ 之间）。

### ★ 功能点的五大基本要素 (必考要素匹配)
进行功能点计数时，必须识别和分类以下五个功能组件：

1.  **内部逻辑文件 (ILF, Internal Logical Files)**：
    *   **定义**：在系统边界内部维护的、用户可识别的逻辑相关数据组。
    *   **举例**：系统数据库中的“用户信息表”、“商品明细表”。
2.  **外部接口文件 (EIF, External Interface Files)**：
    *   **定义**：被其他系统维护，但本系统在运行中需要引用和读取的逻辑数据组。
    *   **举例**：调用微信支付 API 读取微信侧的账单数据。
3.  **外部输入 (EI, External Inputs)**：
    *   **定义**：从系统边界外部传入的数据或控制信息，用以更新内部逻辑文件（ILF）或改变系统行为。
    *   **举例**：用户注册表单提交、修改密码请求。
4.  **外部输出 (EO, External Outputs)**：
    *   **定义**：系统向外部发送的计算或转换结果，包含复杂的业务计算逻辑。
    *   **举例**：系统自动生成的月度财务分析报表、图表。
5.  **外部查询 (EQ, External Inquiries)**：
    *   **定义**：系统向外部提供的数据展示，直接检索数据库并返回，**不包含复杂的业务计算**，也不更新任何内部逻辑文件。
    *   **举例**：点击“查询当前余额”，系统直接从库中读取并展现。

## 🤖 COCOMO 估算模型

**COCOMO (Constructive Cost Model, 构造性成本模型)** 是一种利用历史项目数据建立的经验性估算模型。

### 三个估算级别 (层次考点)

1.  **基本 COCOMO (Basic)**：
    *   **原理**：静态单变量模型。仅基于预估的代码行数（KLOC）来粗略计算工作量和成本。
    *   **特点**：简单、快速，但没有考虑人员素质、硬件限制等客观因素，误差较大。
2.  **中级 COCOMO (Intermediate)**：
    *   **原理**：在基本模型的基础上，引入了 **15 个成本驱动因子**（如：可靠性要求、数据库规模、程序员能力、开发工具的先进性等）来进行系数微调修正。
    *   **特点**：准确度高，是目前最常用的级别。
3.  **详细 COCOMO (Detailed)**：
    *   **原理**：将整个大系统划分为多个子系统，对不同层级（系统级、子系统级、模块级）分别使用不同的成本驱动因子进行非常细致的复合修正。
